# 规模测算与英文全量降级预案

## 1. 为什么必须先算体积

Kindle 词典的查词索引要在打开弹窗时被检索，体积越大越慢。已知能正常使用的大部头词典都在 300 MB 以内：

| 词典 | 体积 |
| --- | --- |
| 英汉汉英医学辞典 | 281.3 MB |
| En-En OALD（压缩版） | 225.6 MB |
| 汉典 | 182.7 MB |
| 中国大百科全书 | 182.5 MB |
| 汉语大词典 | 118.8 MB |

**经验阈值：约 280 MB。** 超过它就要有真机验证的心理准备。

## 2. 体积估算模型

```
HTML 字节数 ≈ 条目数 × (索引标记开销 + 词头字节 × 2 + 释义字节)
             ├ 索引标记开销：idx:entry + idx:orth + <p> + pagebreak ≈ 180 B
             └ 词头字节 × 2：一次进 value 属性（查词键），一次做显示文本
MOBI 体积   ≈ HTML 字节数 × 压缩率 + 索引体积
                 ├ 压缩率：中文（UTF-8）约 0.30–0.40，英文约 0.40–0.50
                 └ 索引体积 ≈ 可查键总数 × 20 B（含词头与全部变形词）
```

## 3. 预估结果

| 目标 | 条目数 | 释义均长 | HTML | MOBI 估算 | 判断 |
| --- | --- | --- | --- | --- | --- |
| 中文全量 | ~140 万 | ~200 字 | ~870 MB | **300–380 MB** | 略高于经验阈值，但同量级可用；需真机确认 |
| 英文全量 | ~690 万 | ~400 字 | ~4.8 GB | **2.2–2.6 GB** | 超阈值 8 倍以上，**必须降级** |
| 英文精选 200 万 | 200 万 | 截断至 150 字 | ~700 MB | **300–350 MB** | 可选 |
| 英文精选 100 万 | 100 万 | 截断至 150 字 | ~350 MB | **150–190 MB** | 舒适 |

结论：

- **中文全量值得直接做**，做完量体积，落在 400 MB 以内就先上真机试。
- **英文全量先做出来量体积**（管线一样，只是数据源换成 enwiki dump），若确认超过 500 MB 就按下面的方案降级——不要先花 20 小时下载完 23.9 GB 才发现设备跑不动。

## 4. 英文降级方案（按性价比排序）

### 方案 A：释义截断（零信息损失风险最低，效果最直接）

把释义截到首句或前 150 个字符。维基首段的前一两句本来就承担"定义"职责，后文多是展开叙述，对查词没用。

- 收益：释义体量直接砍掉 60–70%
- 代价：极低，词典反而更像词典
- 实现：`tsv_from_dump.py` 增加 `--max-len 150 --first-sentence`

### 方案 B：按摘要长度粗筛（零额外数据成本）

长摘要通常对应重要条目。按释义长度分档保留：

| 档位 | 保留条件 | 大致保留量 |
| --- | --- | --- |
| 严格 | 摘要 ≥ 400 字符 | 约 80–120 万（核心条目） |
| 中等 | 摘要 ≥ 250 字符 | 约 250–350 万 |
| 宽松 | 摘要 ≥ 150 字符 | 约 500 万 |

- 收益：无额外下载，一条 SQL 就能落地
- 代价：会误伤"重要但摘要短"的条目（如某些专有名词）

### 方案 C：引入外部重要度信号（更准，但要额外数据）

- **维基官方页面访问量** `dumps.wikimedia.org/other/pageviews/`（按月打包，体量大）
- **Wikidata sitelinks 数量**（跨语言版本数越多越重要；需解析 Wikidata dump）
- **维基百科"核心条目"人工列表**（vital articles，约 5 万条，可直接抓取）

推荐组合：**方案 A 打底 + 方案 B 中档 + 对头部 5 万条用方案 C 强制保留**。

### 不推荐：按字母分卷

把英文词典拆成 `A–F` / `G–M` 等多本，每本降到几百 MB。看似可行，但 **Kindle 一次只用一本默认词典查词**，用户读到 G 开头的词还得手动切换词典，实际体验不可接受。仅在"当纯词典查询、不追求点选即查"的场景下可考虑。

## 5. 决策流程

```
中文：全量 → 量体积
        ├ ≤ 400 MB  → 真机上机验证 → 交付
        └ > 400 MB  → 套用方案 A（释义截断至首句）

英文：先做 20 万条小样量体积 → 线性外推全量
        ├ 外推 ≤ 400 MB → 全量，上机验证
        └ 外推 > 400 MB → 方案 A + 方案 B 中档（约 250–350 万条），
                          头部 5 万条无条件保留
```
