# 自动化工具设计

`scripts/wiki2kindle.py` 是唯一入口：**一条命令，七个阶段，自动决策，自动验收**。

```bash
python scripts/wiki2kindle.py --lang zh
```

## 为什么需要它

在此之前，做一本词典要人工记住四件事，每件都能搞错：

1. 该用哪个解析器（官方 dump 还是 DBpedia 摘要）
2. 该传哪些参数（`--aliases`、`--title`、`--lang`……）
3. **做出来的东西会不会超记录上限**（超了会产出查词坏掉的词典）
4. 做完了怎么判断是好的（光看"编译成功"不够）

这四点全部内置成自动判断与验收。

## 七个阶段

| 阶段 | 做什么 | 自动决策 / 失败处理 |
| --- | --- | --- |
| 1 准备编译器 | 检查 kindling，缺失则下载 | 下载后**必验 SHA256**，不匹配直接删除并退出 |
| 2 准备数据 | 在 `data/` 按语言找 dump 或摘要 | `--source auto` 时优先官方 dump；都没有则提示加 `--download` |
| 3 解析成词表 | 按文件特征选解析器 | 识别 `*.ttl.bz2`/`short-abstracts` → DBpedia；`pages-articles`/`*.xml.bz2` → dump |
| 4 归一别名 | 给消歧义标题补基名别名 | 见下节；失败则退回未归一异名表，不阻断 |
| 5 记录数预算 | 预估正文记录数 | 超线自动降级，两步走（见下下节） |
| 6 打包并编译 | 调 `make_dict.py` 再调 `kindling build` | 打包阶段含正文良构性自检，不合格直接中止 |
| 7 验收 | 解析 `kindling dump` 与构建日志 | 四项检查，任一项不过则退出码 1 |

## 阶段 4：归一别名（消歧义后缀 → 基名）

维基有条目标题形如 `信義區 (臺北市)`。**读者在正文里选中的是「信義區」，词头却带后缀 → 查不到。**
这类标题在中文全量里占 11.5%（147,671 条）：
基名已是独立条目的 34,260 条无需处理，**剩下的是真实漏失**。

处理策略：

| 情形 | 做法 |
| --- | --- |
| 基名本身已是词头 | 跳过（真实条目优先） |
| 基名已在既有异名表（重定向）里 | 跳过，避免同一别名指向两个词条 |
| **基名唯一** | 直接补成别名 |
| **基名有多个候选** | 用「**重定向人气**」定主条目：指向该候选的重定向更多才补；人气不领先则跳过 |

中文全量实测：**新增 52,878 条别名**，另有 9,458 个歧义基名因缺乏人气证据被放弃。

**为什么人气判据很重要**：最初用「释义最短者胜出」，结果把 `信義區` 指到了
`信義區 (基隆市)`（小作品）而不是 `信義區 (臺北市)`。改成重定向人气后，
`信義區 → (臺北市)`、`邹衍 → (战国)`、`民主党 → (美国)` 全部正确。

**成本为零**：别名只进索引、**不占正文记录预算**（实测 130 万条异名只让 INDX 从 416 涨到 959 条，
上限是 65,535）。所以原则是——**能补别名就不要删条目**。用 `--no-enrich` 可整体关闭。

## 阶段 5：记录数预算与自动降级

MOBI 的 PalmDB 记录数是 16 位，**硬上限 65,535**；超了会产出查词指向错位的坏文件。

预估式：

```
正文记录数 ≈ TSV 字节数 ÷ 语言系数
```

超线（默认 `--max-records 62000`，留 5% 余量）时按两步降级：

1. **截断释义**（默认 220 字，句子边界处切）——条目数不变，先砍长尾。
2. **仍超则淘汰最短条目**——按释义长度降序累加，直到落进预算。

选择这个顺序的理由：词典的价值主要来自**能查到**，而不是释义长；
所以先牺牲释义长度，最后才牺牲条目。

## 系数校准：一个必须知道的陷阱

**系数随打包尺度变化，小样本不能代表全量。** 实测同一份中文数据：

| 规模 | TSV | 正文记录 | 系数 |
| --- | --- | --- | --- |
| 小样（约 1.3 万条） | 1.3 MB | 406 | ≈3200 |
| 全量（128 万条） | 369 MB | 53,203 | **6936** |

原因与编译器如何按节打包有关，机制未公开。后果很实际：
**若拿小样本校准出的系数去预估全量，会把 128 万条误判成"超限一倍"。**

所以工具做了两道防线：

- 只有 `TSV ≥ 20 MB 且记录数 ≥ 5000` 的运行才写入校准文件；`--sample` 运行一律不写。
- 取用校准时按 **TSV 体积的对数距离**挑最接近的样本，差 10 倍以上就不采信，回落到内置默认值。

配套的兜底：无论预估如何，**阶段 6 都会用编译后的真实 `rec_count` 做验收**，
所以预估偏差不会导致交付一个坏文件——最坏情况是降级过头或降级不足。

## 缓存与重跑

| 产物 | 位置 | 失效条件 |
| --- | --- | --- |
| 解析结果 | `<work>/source.tsv`、`aliases.tsv` | `--force`，或换 work 目录 |
| 降级结果 | `<work>/budget.tsv` | `--force` |
| 词典工程 | `<work>/dict/` | 每次重跑都重建 |
| 构建日志 | `<work>/build.log` | 每次重跑覆盖 |
| 运行报告 | `<work>/report.json` | 每次重跑覆盖 |

解析是最贵的一步（中文全量 14 分钟），所以单独缓存；重跑往往只需几十秒。

## 阶段 6 的四项验收

| 检查 | 为什么必须查 |
| --- | --- |
| `palmdb.rec_count ≤ 65535` | 超了就是坏文件，但编译器不一定报错 |
| `mobi.orth_index` 存在且非 0 | 没有正字法索引就不是可查的词典，只是本电子书 |
| `exth[105]` 含 `Dictionaries` | 设备靠它把文件列进词典列表 |
| 日志无 `N / N entries not found in text blob` | **最隐蔽的一项**：词头定位失败时文件照样能生成，但查词指向错位或空白 |

## 用 --sample 快速验证

`--sample N` 只处理一小部分数据，用来在正式跑之前确认整条链路通：

```bash
python scripts/wiki2kindle.py --lang zh --sample 3000   # 约 10 秒
```

dump 分支按约 2.2 页/词条放大页数（dump 里还混着大量重定向页）。

## 已知边界

- **英文全量仍不能靠本工具单本自动完成**：690 万条超过单本上限，需要分卷，
  而分卷是否可用取决于 Kindle 是否回退查询非默认词典（待真机验证）。见 [05](05-scaling-english-plan.md)。
- 预算预估的系数是**按语言**校准的，同一语言换数据源（dump ↔ DBpedia）系数会有差异，
  但同数量级内可用。
